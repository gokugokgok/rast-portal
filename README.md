# Portal + SearXNG — 表示件数・検索地域・検索方針の設定

PortalとSearXNGを一つのRenderサービスで動かします。検索時のURLは `/`、タブ名は `Portal` で固定。検索・設定変更・ページ送りはPOSTです。JavaScript有効時は画面だけ更新し、検索ごとの履歴項目を増やしません。Google/BraveのAPIキー、別のSearXNGサイトへの登録は不要です。

## 今回追加した設定

右上の歯車から変更します。検索結果があるときに設定を変えると、1ページ目から検索し直します。検索前なら次の検索に適用します。設定はこの画面を開いている間だけ保持し、CookieやlocalStorageには保存しません。

| 設定 | 選べる内容 |
|---|---|
| 1ページの表示件数 | 最大10・20・40・60・100件。初期値20件 |
| 検索地域・言語 | 日本語/日本、英語/アメリカ、英語/イギリスなど111通り。地域指定なしも選択可能 |
| 検索方針 | 高速・バランス・広く検索。初期値バランス |
| 一致条件 | 通常の検索・入力全体を完全一致 |
| セーフサーチ | オフ・標準・厳格。初期値標準 |
| 外観 | システムに合わせる・ライト・ダーク |

件数は表示の上限です。検索元の応答、重複、検索語によって上限より少なくなることがあります。多く表示するためには追加の取得が必要なので、100件は10件より時間がかかる場合があります。

検索地域は固定したSearXNG版の対応ロケールから選び、検索元へ渡します。国だけでなく検索言語との組み合わせです。国に対応しない検索元では別の地域へフォールバックする場合があります。接続元IPやGPS位置の変更、国を厳密に限定する機能ではありません。

「完全一致」は、入力全体を引用符で囲んで検索元へ送ります。固有名詞や決まった表現を探す際に便利です。引用符の解釈は検索元によって異なり、結果が減る場合もあります。通常検索では `site:example.com 検索語` や手入力の引用符など、対応する検索元の検索構文も使えます。

## 精度と速度の調節

| 検索方針 | 検索元 | 1回のSearXNG検索での待ち時間設定 |
|---|---|---|
| 高速 | 有効な検索元の最大2つ | 1.5秒 |
| バランス | 最大3つ | 2.2秒 |
| 広く検索 | 最大4つ | 3.5秒 |

各カテゴリでGoogle、Bing、DuckDuckGo、Braveの順に有効な検索元を選びます。SearXNGの複数検索元による関連度順を使い、Portal側で同じURLの重複を整理します。広告用のutm_*・gclid・fbclid・msclkidとURL末尾のフラグメントだけが異なる結果もまとめます。実際の検索の意味に関わるURLパラメーターは残します。画像は同じ掲載サイトでも異なる画像なら別の結果として扱います。

速さを優先する場合は「10件＋高速」。幅広く探す場合は「バランス」か「広く検索」と地域・言語の指定を試してください。完全一致は不要な候補を絞るための設定で、すべての検索語で精度が向上する保証ではありません。高速モードでは待ち時間と検索元を減らすため、結果が少なくなることがあります。

- 表示件数を減らしても、取得済みの残りを捨てずに次ページへ回します。件数を変えると取得済みの結果を新しい件数で区切り直します。
- 検索語・カテゴリ・セーフサーチ・地域・検索方針・一致条件ごとに結果をサーバーメモリへ保持し、必要な追加ページだけ取得します。表示件数と画面のページ番号はこの取得済み結果を分割する条件です。
- 最初は検索元の1ページだけ取得します。そのページで足りる場合、先のページは取得しません。追加取得が必要な場合は直前の取得件数に合わせて同時最大3ページ、1回のPortal検索で最大6ページまで取得します。到着順によって表示の順番が入れ替わらないよう、検索元のページ順にまとめます。
- 取得済みの結果は、検索条件ごとに有効期限60秒・最大24条件・合計4MBまでです。同時に同じ条件の検索が来た場合は重複取得を抑えます。結果なしの障害はキャッシュしません。
- ブラウザ内でも同じ検索語の表示ページを最大12件・45秒保持します（大きな画像ページなどは保持数を減らします）。地域や件数などの設定を区別します。新しい検索語や「画面をクリア」で破棄します。
- Wikipediaの概要、サイトアイコン、一覧画像は検索結果本体と独立して読み込みます。Wikipediaは5分のサーバーキャッシュと現在の検索語だけの画面内キャッシュを使います。

上の秒数はSearXNGが検索元の応答を待つ設定です。ページの追加取得、DNS、混雑、画像、起動時間を含む画面全体の所要時間ではありません。Portalから内部SearXNGへの読み取りタイムアウトは5秒です。

RenderのFreeサービスは15分間アクセスがないと休止し、再開まで約1分かかる場合があります。この起動待ちは検索処理の改善では解消しません。公式説明: https://render.com/docs/free

## 表示機能

- Chromeの新しいタブとGoogle検索に近い検索欄・上部検索バー・カテゴリタブ。
- 「すべて」「画像」「動画」「ニュース」。動画の再生は掲載サイトで行います。
- 検索結果のサイトアイコンをサーバー経由で取得。DuckDuckGoのアイコン配信にドメインだけを送り、取得できなければそのサイトの `/favicon.ico` を試します。表示できない場合は地球マークです。
- アイコンは画面に近いものから同時2件。PNG/JPEG/GIF/WebP/AVIFとICOに対応し、SVGやHTMLは読み込みません。アイコンの成功キャッシュは1時間・最大128件・1件64KBまで、失敗は60秒です。
- 同じ画像の登録IDを再利用し、件数変更や再検索で使うIDを増やしすぎないようにしています。大きな画像ページの画面内キャッシュも少なめにし、古いIDが切れて画像を読み込めなくなる状況を減らします。
- 画像一覧は画面に近いものから同時3件。プロキシが混雑した場合は最大2回再試行します。プレビューを開くと表示済みのサムネイルをすぐ表示し、元画像は後から取得。元画像の取得に失敗してもサムネイルを残します。
- 「すべて」の右側に日本語Wikipediaの関連する記事の概要・出典リンク。スマホでは結果の上に表示します。概要取得を待たずに検索結果を操作でき、同じ検索語のページ送りでは概要を再取得しません。概要にはJavaScriptが必要です。
- 「1・2・3・4・5」と前へ・次へ。最大10ページで切り替えます。番号は移動先であり、総ページ数ではありません。
- 表示件数・地域・検索方針・一致条件・セーフサーチは、カテゴリ変更・ページ送りでも引き継ぎます。
- 「画面をクリア」で入力・結果・プレビューを消します。

SearXNGのJSONには確実な次ページフラグがありません。空または重複だけの追加ページで終了を判断します。期限切れ後の遠いページ指定や、追加取得の上限で指定位置に届かない場合は、警告と取得済みのページを表示します。1条件あたり最大1000結果、内部検索元は最大50ページまでです。

## すでにGitHub・Renderで公開している場合

1. ZIPを展開します。
2. `portal-searxng` フォルダの**中身**を、既存GitHubリポジトリの直下へ上書きアップロードします。
3. `Commit changes` で保存します。
4. Renderで対象サービスの `Manual Deploy → Deploy latest commit` を実行します。自動デプロイが有効ならCommit後のデプロイ完了を待ちます。

今回、新しく追加するファイルは `searching.py`、`regions.json`、`tests/test_searching.py` です。更新したファイルは `app.py`、`requirements.txt`、`searxng-settings.yml`、`templates/index.html`、`templates/results.html`、`static/app.js`、`static/style.css`、`media.py`、`README.md`、`tests/test_app.py`、`tests/test_media.py`。ZIP一式で上書きすると差し替え漏れを防げます。

`templates` と `static` は既存の同名フォルダを更新します。`templates/templates` や `portal-searxng/portal-searxng` にしないでください。リポジトリ直下に `app.py`、`Dockerfile`、`render.yaml`、`searching.py`、`regions.json` があることを確認します。

## 初めてGitHub・Renderに入れる場合

1. GitHubでリポジトリを作ります（例: `portal-new`）。
2. `Add file → Upload files` でZIPを展開した `portal-searxng` の中身をアップロードします。
3. `Commit changes` で保存します。
4. https://dashboard.render.com/ の `New → Blueprint`。
5. GitHubを接続し、保存したリポジトリを `Connect`。
6. Blueprint Nameは任意、Branchは `main`、Blueprint Pathは `render.yaml`。
7. サービス名 `portal-searxng`、Runtime `Docker`、Plan `Free` を確認して `Deploy Blueprint`。
8. 完了後、サービスの `https://….onrender.com` を開きます。APIキー入力は不要です。

Blueprintを使わない場合は `New → Web Service` で同じリポジトリを接続します。

| 項目 | 値 |
|---|---|
| Name | portal-searxng |
| Runtime / Language | Docker |
| Root Directory | 空欄（直下にファイルを置いた場合） |
| Dockerfile Path | ./Dockerfile |
| Docker Command | 空欄 |
| Plan | Free |
| Health Check Path | /health |
| APIキー | 不要 |

古いPython/Brave API版のサービスを使っていた場合は、このDocker版を別サービスとして作ります。旧サービスは自動で削除されません。APIキー入力欄が残る場合は、新しい `render.yaml` をCommitしてから作成画面を開き直します。

## SearXNGの設定

SearXNGは内部の `127.0.0.1:8888` だけで動き、外部へ公開するのはPortalです。Google・Bing・DuckDuckGo・BraveのWeb/画像/動画/ニュース（計16エンジン）を設定済みです。Brave Search APIは使いません。

検索元を停止する場合は `searxng-settings.yml` 末尾の対応する `disabled` を `true` にします。Portalもこの設定を読み、明示的な検索元選択から除外します。画像・動画・ニュースには `google images`、`google videos`、`google news` など別々の名前があります。

```yaml
engines:
  - name: google
    disabled: true
  - name: bing
    disabled: false
```

この例は変更する部分の抜粋です。ファイル全体をこの2項目だけに置き換えず、該当する項目の値を変更してください。変更後はGitHubでCommitし、Renderを再デプロイします。全検索元を停止すると検索できません。

`search.formats` の `json` は削除しないでください。Portalからの取得に必要です。検索元はRenderの接続を拒否したり、CAPTCHA・アクセス制限を返したりする場合があります。公式APIと同じ安定性や、Googleと同じ検索結果は保証しません。

新しく取得する内部検索ページには、サービス全体で毎分30回の制限を設けています。表示件数を増やすと複数回分を使う場合があります。キャッシュ再表示は回数に含めません。利用者のIPを保存せず、全体の回数だけを管理します。Wikipedia取得は同時2件までです。

## プライバシーと画像取得

- 検索履歴DB・Cookie・localStorage・広告・アクセス解析・外部フォントは使いません。Portal/SearXNGのアクセスログと検索処理ログを出さず、検索元の生エラーを表示しません。
- 検索語はRender上のPortal/SearXNGと選択した検索元へ届きます。利用者のIP・Cookie・ブラウザ情報は検索元へ転送しません。検索元にはRenderサーバーからの接続が見えます。
- 「すべて」の概要検索では、入力した検索語をサーバーから日本語Wikipediaへ送ります。検索地域を変えても概要は日本語Wikipediaです。関連する記事が、入力の意図と違う場合があります。
- キャッシュのキーは検索条件のSHA-256です。結果や概要本文は一時的にメモリにあり、利用者との関連付けやファイルへの保存は行いません。期限切れの項目は次のアクセス時に削除し、再起動でも消えます。Wikipediaは5分・最大64件・合計512KBです。
- 画像とアイコンはランダムな `/media/ID`・`/icon/ID` を使い、URLに検索語や取得先URLを載せません。ブラウザはプロキシから取得した画像を一時的なBlob URLで表示します。検索し直す・画面をクリアする際に解放します。
- 画像URLとランダムIDは最大10分・600件までサーバーメモリへ保持します。アイコンのサイトとランダムIDも10分・最大600件です。画像URL自体に検索語が含まれる場合があります。
- 取得済み画像は有効期限5分・合計24MB、失敗は10秒だけ保持します。同じ画像URLの同時取得をまとめます。
- 画像取得はPNG/JPEG/GIF/WebP/AVIF・1件8MBまで、最大3候補、サーバー側の同時取得4件。一覧は候補ごと3秒・全体6秒、元画像のプレビューは候補ごと15秒・全体24秒です。DNSなどで期限を超える場合があります。
- 公開IPだけに接続し、DNSで確認したIPへ固定します。リダイレクト先も検証し、非公開IPやローカルネットワークには接続しません。利用者のCookieやRefererは送りません。HTMLやSVGは表示しません。
- POST・no-store・no-referrer・固定タイトル・ページ復元時のクリアを設定しています。入力と検索結果は表示中のDOM・メモリにあります。端末・ブラウザ・拡張機能・ホスティング側の保存を完全には制御できません。
- HTTPSでアクセスしてください。外部リンクを開くと訪問先へ直接接続し、そのURL・タブ名が表示されます。匿名ビュー機能はありません。

## 公開後の確認

1. 検索結果が表示される。
2. URLが `/`、タブ名が `Portal` のまま。
3. 歯車で件数・地域・検索方針を変えられる。
4. ページ送りとカテゴリ変更で設定が引き継がれる。
5. 「画面をクリア」で入力と結果が消える。

| 状態 | 対処 |
|---|---|
| TemplateNotFound | templates内のindex.html/results.htmlを確認 |
| regions.jsonやsearching.pyがない | 新規ファイルもGitHub直下へ追加 |
| 起動に時間がかかる | Freeサービスの休止からの起動待ちを確認 |
| 検索元が応答しない | 少し待つか「広く検索」を試す |
| 結果が少ない | 完全一致を通常へ戻す、地域・検索方針を変える |
| 429が出る | 1分ほど待ち、表示件数を減らす |
| メモリ不足 | 検索元を減らすかサービスのプランを見直す |

## ローカル起動と検証

DockerがあるPCで:

```bash
docker build -t portal-searxng .
docker run --rm -p 10000:10000 portal-searxng
```

http://localhost:10000/ を開きます。固定したSearXNGコミット: `6a0ac6a39112d4a73a80eda4564d68ba090a9eff`。地域リストはこの版の `sxng_locales.py` から作成した111項目です。

```bash
python -m unittest discover -s tests -v
```

Portal・画像プロキシ・アイコン・キャッシュ・新しい検索条件とページ分割の48テストを確認しています。今回の追加検証は、10〜100件の実際の分割、結果の抜けと重複の防止、地域/方針/完全一致の送信、設定ごとのキャッシュ分離、取得の並行実行での順番、途中の失敗後の再取得、同じ検索の重複通信抑止、不正設定の拒否、遠いページ指定の取得上限です。

テスト用の検索結果・概要・画像を使ったブラウザ確認も行いました。設定変更、100件表示、ページ番号、設定の引き継ぎ、同じページへのキャッシュ復帰、Wikipediaの独立読み込み、アイコン、プレビュー、スマホ幅、暗いテーマ、固定URL/タイトル/履歴、Cookieなし、JavaScript無効時のフォーム検索を確認しています。

今回の環境ではSearXNGのネイティブ依存 `curl_cffi` が単体importでもSIGBUSで停止するため、実バックエンドでの再確認は未完了です。以前の版では2サーバーの起動と内部接続、ヘルスチェック、16エンジンの設定読込を確認しています。Dockerは新しく依存をインストールし、この検証用の依存フォルダは配布ZIPに含めません。この環境ではDockerビルド・Render公開も未実行です。実際の外部検索・Wikipedia・画像・アイコンを取得した速度や精度の測定はしていません。公開後の確認が必要です。
